# Explorations are isolated from library gates

`explorations/` is a lane for standalone experiments that trades the library's guarantees for speed: explorations join the pnpm workspace (one install, `workspace:*` access to `@repo/ui`) but are excluded from every library gate — the main CI pipeline, the pre-commit turbo run, Prettier, and ESLint all filter the folder out. Their only obligations are the deploy contract (`build` → `dist/`, folder name = site name) and Conventional Commit messages, which can't be folder-scoped. A dedicated path-filtered workflow builds only the explorations a change touches, so a broken exploration can never block library work and a library PR never waits on explorations. Deployment is split deliberately: CI deploys the canonical site (`/<project>/<name>/`) from main with a project token, while `pnpm publish-exploration` deploys per-person draft sites (`/<name>-<user>/`) with personal tokens — so the canonical URL always reflects merged work and a merge can never clobber someone's freshly published WIP.

**Considered options:** running explorations through the shared pipeline (rejected: designer experiments and library PRs would block each other); keeping them outside the workspace entirely (rejected: consuming the source-only `@repo/ui` from outside is painful and every exploration would need its own install); publishing drafts and canonical deploys to the same site (rejected: merges would overwrite newer drafts and the shared URL could show unmerged work).

**Consequences:** a `@repo/ui` change that breaks a dependent exploration surfaces on that exploration's next PR or deploy, not on the ui PR — accepted, the library is never held hostage by experiments. Sites outlive their folders: deleting an exploration requires manual `sites delete` cleanup (nothing automated deletes content from a namespace humans also publish drafts into). Workspace membership means explorations inherit the pinned Node/pnpm versions and `minimumReleaseAge` for new dependencies.

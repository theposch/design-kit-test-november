# PR previews are CI-owned sites

Every pull request gets its own Storybook on Metalab Sites at `/<project>/pr-<n>-storybook/`, published from the `ci` job and announced in a single PR comment that later pushes edit in place (URL, head SHA, timestamp). The preview deploys whenever the Storybook _build_ succeeds — ahead of lint, typecheck, and tests — because the moment a designer most needs to look at a PR is often exactly when a gate is red (a contrast failure against a new palette, a play function mid-adjustment); a broken build still yields no preview. The deploy and comment steps are `continue-on-error`, so a Sites or GitHub API failure can never block a merge, and a newer push cancels the in-flight run (workflow concurrency) so a stale build cannot overwrite a fresher preview. When the PR closes — merged or not — a `preview-cleanup` job deletes the site and edits the comment to say so.

The `pr-<n>-` prefix is reserved to CI across the shared project namespace (`pnpm new-exploration` rejects it). That reservation is what makes automated deletion safe: `docs/adr/0007` forbids CI from deleting sites because explorations share the namespace with human-published drafts, and that rule stands unchanged for every name outside the prefix.

**Considered options:** previews only when the full gate is green (rejected: hides the preview exactly when review needs it, and the required `ci` check already guards mergeability); `pull_request_target` so Dependabot and fork PRs receive the token (rejected: runs untrusted code with secrets — those PRs simply get no preview); leaving closed PRs' sites in place (rejected: dozens of dead ~9 MB sites per engagement and a `sites list` full of noise); a marketplace sticky-comment action (rejected: a third-party dependency with repo write access, when `gh api` and a 60-line script do the same).

**Consequences:** Dependabot and fork PRs get no preview and no comment (secrets are withheld on `pull_request` for them). A PR whose build never passed has no site, so cleanup checks `sites list` before deleting. The prefix leaves room for exploration previews (`pr-<n>-<exploration>`) under the same ownership rule, but explorations already have a per-person draft lane, so none are built today.
